# Telco Customer Churn Predictor

A rebuild of the original notebook as a proper 3-tier application:

- **Model** (`model/`) — scikit-learn pipeline trained on the Telco churn dataset
- **Backend** (`backend/`) — FastAPI service that runs predictions and stores every result in MySQL
- **Frontend** (`frontend/`) — Streamlit dashboard that collects customer details and shows results + history

```
telco_churn_app/
├── requirements.txt
├── database/
│   └── schema.sql              # MySQL table definition
├── model/
│   ├── telco_customer_churn.csv
│   ├── train_model.py          # cleans data, trains, saves the pipeline
│   ├── churn_pipeline.pkl      # generated by train_model.py
│   ├── metrics.json            # generated by train_model.py
│   └── feature_importance.csv  # generated by train_model.py
├── backend/
│   ├── .env.example
│   ├── config.py                # loads settings from .env
│   ├── database.py              # MySQL connection + queries
│   ├── schemas.py                # request/response data models
│   ├── predictor.py              # loads the model, runs predictions
│   └── main.py                   # FastAPI app (the API itself)
└── frontend/
    └── streamlit_app.py          # the dashboard the user interacts with
```

## How the pieces fit together

```
 Streamlit (frontend)  --HTTP-->  FastAPI (backend)  --SQL-->  MySQL
        |                              |
   collects form input          loads churn_pipeline.pkl
   shows prediction              runs prediction
   shows history                 saves result to MySQL
```

The frontend never touches the model or the database directly — it only
talks to the backend over HTTP. That separation means you could swap the
frontend for a mobile app later, or the database for PostgreSQL, without
touching the other pieces.

## 1. Install dependencies

```bash
python -m venv venv
source venv/bin/activate        # on Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Set up MySQL

Make sure a MySQL server is running, then create the database and table:

```bash
Get-Content database\schema.sql | & "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p
```

## 3. Train the model

```bash
cd model
python train_model.py
```

This reads `telco_customer_churn.csv`, cleans it, trains both a Logistic
Regression and a Random Forest model (same comparison as the original
notebook), and saves the better-performing one as `churn_pipeline.pkl`,
along with `metrics.json` and `feature_importance.csv`.

## 4. Configure and start the backend

```bash
cd backend
cp .env.example .env
# edit .env with your real MySQL username/password
uvicorn main:app --reload --port 8000
```

Visit `http://localhost:8000/docs` to try the API directly (interactive
Swagger docs, generated automatically by FastAPI).

## 5. Start the dashboard

In a second terminal:

```bash
cd frontend
streamlit run streamlit_app.py
```

This opens the dashboard in your browser (usually `http://localhost:8501`).
Fill in a customer's details and click **Predict Churn** — the result is
shown immediately and also saved to MySQL. The **Prediction History** tab
reads that saved history back through the API.

## Notes on the model

- `TotalCharges` arrives as text in the raw CSV (a few brand-new customers
  have a blank value); it's converted to numeric and those few rows are
  dropped, exactly as in the original notebook.
- Instead of manually one-hot encoding columns and matching them up by
  hand (as the original notebook's Streamlit app did, which only handled
  3 of the ~19 input fields), the whole preprocessing + model is one
  scikit-learn `Pipeline` object. This means the API can accept the full,
  raw set of customer fields, and adding a new feature later only means
  changing `train_model.py`.
- Both models are trained and compared on F1-score for the "will churn"
  class (not plain accuracy), because the dataset is imbalanced
  (~26% churn) — `class_weight='balanced'` is used for the same reason.
